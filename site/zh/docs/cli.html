CLI 与配置

命令、参数与 TOML 配置参考。

命令

Agent 默认模式

$sudo rezolus <CONFIG>

通过 eBPF 采集度量。需要 root 权限。监听 0.0.0.0:4241。

Exporter

$rezolus exporter <CONFIG>

从 agent 拉取数据，并在 :4242 暴露 Prometheus 度量。

Recorder

$rezolus record [OPTIONS] [-- <COMMAND>...]

不带任何参数时，它会记录本机 agent（http://localhost:4241）到 rezolus.rez ，直到 ctrl-c。输出文件的扩展名决定格式，因此 --format 通常不需要。

--url <URL> 要记录的端点 [默认：http://localhost:4241]
-o, --output <PATH> 输出路径；.rez | .parquet | .raw 决定格式 [默认：rezolus.rez]
-i, --interval <INTERVAL> 采集间隔 [默认：1s]
-d, --duration <DURATION> 记录固定时长后停止
-f, --format <FORMAT> rez|parquet|raw —— 仅当路径无法表明格式时才需要
-l, --label <KEY=VALUE> 为 .rez 记录打标签（可重复）；source/host 自动填充
-m, --metadata <KEY=VALUE> 文件级元数据，适用于所有格式（可重复）
--config <FILE> 多端点记录的 TOML 配置
--endpoint <URL> 带选项的端点（可重复），url[,source=][,role=][,protocol=]
--separate 为每个端点分别写文件，而不是合并成一个
-v, --verbose 提高日志详细程度（可叠加）
# 记录本机 agent 直到 ctrl-c → rezolus.rez
$rezolus record
# 以 100ms 间隔记录 30 秒
$rezolus record -o run.rez -i 100ms -d 30s
# 仅在基准测试运行期间记录（类似 perf record）
$rezolus record -o bench.rez -- ./bench.sh --iters 100
# Prometheus 数据源需要用 parquet
$rezolus record --url http://host:9090/metrics -o svc.parquet -d 5m

Hindsight

$rezolus hindsight <CONFIG>

滚动环形缓冲区。发送 SIGHUP 触发快照。

状态

$rezolus status [OPTIONS] [ENDPOINT]

询问运行中的 agent 的状况：版本、运行时长，以及按采样器汇总的健康情况。不带参数时询问本机的 agent。

ENDPOINT 要询问的 agent [默认：http://localhost:4241]；直接写 host 或 host:port 也可以
--json 输出原始的 /status JSON

退出码： 一切正常时为 0；只要有采样器处于 degraded、failed 或 pmu-limited 状态即为 1——因此可以直接用作健康检查或就绪探针。

# 本机的 agent 健康吗？
$rezolus status
# 另一台主机，用简写形式
$rezolus status web-01
# 在脚本中用它作为判断条件
$rezolus status || echo "agent is unhealthy"

Viewer

$rezolus view [OPTIONS] [INPUT] [EXPERIMENT]
INPUT 第一份采集：parquet、.rez 归档、agent URL，或 alias=parquet
EXPERIMENT 可选的第二份采集，用于 A/B 对比
-l, --listen <ADDR> Viewer 监听地址（例如 127.0.0.1:8080）
--templates <DIR> service-extension 模板 JSON 所在目录
--category <NAME> 启用类别模式（例如 inference-library）
--proxy-allow <PATTERN> 为 URL 代理放行的主机模式（可重复）
--proxy-allow-any 完全关闭代理白名单（信任所有来源）
--tui 使用终端界面而非浏览器（需要文件或 agent URL）
--cache-size-mb <MB> row group 缓冲缓存大小 [默认：500]
-v, --verbose 提高日志详细程度
# 查看一份记录
$rezolus view output.parquet
# 查看 .rez 归档（含两份记录的 .rez 会渲染为 A/B）
$rezolus view out.rez
# 查看实时 agent
$rezolus view http://localhost:4241
# 在终端中浏览，无需浏览器
$rezolus view --tui out.rez

MCP Server

$rezolus mcp [SUBCOMMAND]
analyze-correlation <FILE> <Q1> <Q2>
describe-recording <FILE>
describe-metrics <FILE>
detect-anomalies <FILE> [QUERY]
query <FILE> <QUERY>
extract-features <FILE>

每个 <FILE> 都可以是 .parquet or a .rez；格式由内容自动判断。不带子命令时， rezolus mcp 会作为 stdio MCP 服务器运行，供 LLM 客户端连接。

# 对一份记录执行一次性 PromQL 查询
$rezolus mcp query out.rez 'sum(rate(cpu_cycles[1m]))'
# 扫描所有度量以发现异常
$rezolus mcp detect-anomalies out.rez

记录工具

$rezolus recording <SUBCOMMAND> [OPTIONS]

对记录的离线操作—— .parquet 文件与 .rez 归档都支持。查看元数据、裁掉不需要的部分、嵌入服务 KPI 定义、合并多来源采集，或转换旧格式。 rezolus parquet … 仍可作为别名使用。

metadata

显示一份记录的文件级与列级元数据。

-i, --input <FILE> 要查看的记录（.parquet，或 .rez 的 manifest）
--schema 仅显示列级元数据
--file 仅显示文件级元数据
--geometry 仅显示表结构与 row group 布局
--field <KEY> 打印某个文件级元数据键
--json 输出 JSON（便于脚本处理）

annotate

把 service-extension 的 KPI 查询（及相关元数据）嵌入记录，使 Viewer 能把它们渲染成图表。

FILE 要注解的 parquet（除非指定 ‐‐output，否则就地覆盖）
--queries <JSON> 自定义 service-extension JSON（覆盖模板）
--templates <DIR> 用于解析 KPI 的模板目录
--source <NAME> 用于匹配模板的 source 标签 members
--node <NAME> 节点名，读取方为 combine 用于多节点合并
--filter 仅保留 KPI 引用到的列
--systeminfo <JSON> 嵌入或覆盖记录中的 systeminfo
--add-events <JSON> 向文件追加事件
--event <SPEC> 单条事件定义（可重复）
--clear-events 删除所有已有事件
--overwrite 允许覆盖已有注解
--undo 移除此前添加的注解

combine

把多个 parquet 文件合并成一个——多节点 rezolus、多实例服务，或对比模式的 A/B 包。

FILES... 要合并的输入（parquet，或单记录 .rez）
-o, --output <FILE> 输出 parquet 路径
--pinned <NAME> 默认显示的 rezolus 节点
--ab <B=SRC> <E=SRC> 打包为 A/B 对比 tarball——一个参数，两个值： --ab baseline=… experiment=…
--category <NAME> 为该包标注类别模板
--bypass-time-check 跳过时间戳对齐校验

filter

把记录缩减到真正需要的部分——parquet 中被 service-extension KPI 引用的列，或 .rez中的整个采样器。在分享聚焦报告之前很有用。

FILE 要过滤的记录（.parquet，或配合 --samplers 的 .rez）
--samplers <A,B,...> 用于 .rez：要保留的采样器（.rez 必填，parquet 忽略）
--queries <JSON> 自定义 KPI JSON（覆盖已嵌入的或模板中的）
--templates <DIR> 用于解析 KPI 的模板目录
-o, --output <FILE> 输出路径（默认就地覆盖）

convert

把原始 msgpack 记录（来自 record -o out.raw）转换为 parquet。输入可以是未压缩或 zstd 压缩，由内容自动判断。

FILE 要转换的原始记录
-o, --output <PATH> 输出 parquet 路径（默认：把输入的扩展名换成 .parquet）
--interval <DURATION> 覆盖推断出的采样间隔
--systeminfo <PATH> 补写原始流中不含的 systeminfo
--descriptions <PATH> 补写度量的帮助文本（只能在这里设置）
-m, --metadata <KEY=VALUE> 为输出打标签（可重复）
--force 覆盖已存在的输出

upgrade

把 v1/v2（tar）的 .rez 重写为当前的 v3（SQLite）容器。分段数据逐字节原样搬运。若输入已经是 v3，会被拒绝而不是复制。

FILE 要升级的 .rez 归档
-o, --output <REZ> 写入此处，而不是就地替换
# 查看
$rezolus recording metadata -i out.rez
# 用模板目录中的 KPI 进行注解
$rezolus recording annotate recording.parquet --templates ./templates
# 把两份采集合并为 A/B 包
$rezolus recording combine before.parquet after.parquet \
  --ab baseline=before experiment=after \
  -o compare.parquet.ab.tar
# 把两个单记录 .rez 组装成一个 A/B 归档
$rezolus recording combine baseline.rez experiment.rez -o ab.rez

配置

每种模式都使用一个 TOML 配置文件。示例位于 config/ directory.

Agent

config/agent.toml
# 通用设置
[general]
listen = "0.0.0.0:4241"
# 日志
[log]
level = "info" # error | warn | info | debug | trace
# 调度器调优
[scheduler]
policy = "normal" # normal | round_robin | fifo
# 所有采样器的默认值
[defaults]
enabled = true
# 针对单个采样器的覆盖
[samplers.cpu_usage]
enabled = true
[samplers.scheduler_runqueue]
enabled = true

Exporter

config/exporter.toml
[general]
listen = "0.0.0.0:4242"
source = "http://127.0.0.1:4241"
[prometheus]
histogram = "summary" # summary | histogram

Hindsight

config/hindsight.toml
[general]
interval = "1s"
duration = "1h"
source = "http://127.0.0.1:4241"
output = "/var/lib/rezolus/hindsight.parquet"
listen = "0.0.0.0:4242" # 可选的 HTTP API
