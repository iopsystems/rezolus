运行模式

Rezolus 是一个二进制，包含六个子命令。每种模式负责可观测性工作流中的不同阶段。

monitoring

Agent

sudo rezolus <config.toml>

核心采集引擎。把 eBPF 程序挂载到内核 tracepoint 与 kprobe 上，采集 CPU、调度器、块 I/O、网络、内存、TCP 与系统调用的度量，并通过 4241 端口以 JSON 和 msgpack 格式对外提供数据。

upload

Exporter

rezolus exporter <config.toml>

从 agent 的 msgpack 端点拉取度量，并在 4242 端口以 Prometheus 格式提供。可把直方图转换为可配置的 summary 分位数，专为 Prometheus 抓取而设计。

fiber_smart_record

Recorder

rezolus record [-o out.rez]

按需把度量采集到 .rez 归档文件（或 Parquet）。连接到运行中的 agent，按可配置的间隔与时长写入高保真快照。非常适合基准测试与性能工程。

history

Hindsight

rezolus hindsight <config.toml>

在磁盘上维护高分辨率度量的滚动环形缓冲区。可通过 SIGHUP 或 HTTP API 触发快照，并支持按时间范围查询，提取故障前后的时间窗口。

dashboard

Viewer

rezolus view <input> [listen]

基于 Web 的交互式仪表盘，可浏览 Parquet 记录，也可从运行中的 agent 实时读取。内置 TSDB 并支持 PromQL 查询，为每个度量类别预置了仪表盘。

smart_toy

MCP Server

rezolus mcp [subcommand]

AI 引导的分析服务器。提供用 PromQL 查询记录、检测异常、分析度量之间的相关性，以及描述记录元数据的工具。

eBPF 集成

Rezolus 使用 libbpf-rs 管理 eBPF 程序。BPF 程序用 C 编写（.bpf.c 文件），与对应的 Rust 模块放在一起，并在构建时通过 build.rs.

运行时，agent 把这些程序挂载到内核 tracepoint 与 kprobe 上，以接近于零的开销获得内核级可见性——被插桩的度量无需轮询 /proc 或 /sys 。

要求： Linux 内核 5.8 及以上，并需要 root 权限。macOS 构建不含 eBPF 采样器。

关键技术细节

  • • 异步运行时： Tokio，线程数极少
  • • HTTP 框架： Axum
  • • 度量库： metriken crate
  • • 采样器注册： linkme 以 distributed slice 做静态注册
  • • 数据格式： Parquet via metriken-exposition
  • • 硬件拓扑： systeminfo crate
  • • 架构： x86_64 与 ARM64
