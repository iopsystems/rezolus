# Sensors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Collect and display Linux hardware sensors for issue #1203 with Thor fixture validation.
**Architecture:** Shared sysfs discovery and driver decoding feed an interval-throttled blocking sampler. Native sensor identities survive recordings; board interpretation is optional. Conditional dashboard charts expose every family.
**Tech Stack:** Rust, metriken gauge/acquisition groups, Tokio, existing dashboard and tempfile test support.
**Spec:** `docs/superpowers/specs/2026-09-17-sensors-design.md`

## Global Constraints

- No hardware writes or subprocess-based telemetry.
- Opt-in `sensors`; default 5-second read cadence; 60-second rediscovery.
- 256 lifetime identities per family; slots never relabeled or reused.
- No new dependency required; Linux sampler and non-Linux schema registration.
- Thor fixture is evidence of layout, not of hardware timing or Orin support.
- No publication to GitHub without authorization.
